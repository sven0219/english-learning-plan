# Day 2 — API Release Timeline

## 1. Daily Passage

> We are planning a small API release for the test environment. The code review is complete, but the release time is still TBD, or to be determined. Before we choose a date, we need one more performance test. From a business perspective, it is better to delay the release than to create an avoidable service problem. Is this timeline realistic for the testing team? If the test passes on Wednesday, we can release on Thursday morning. If it fails, we will move the release to next week. The final date will be TBC, or to be confirmed, after Wednesday’s review. Let us agree on the decision point now. I will prepare the test, and the project team will confirm the schedule.

## 2. Key Meeting and Business Phrases

- `Before we choose a date, we need ...` — 在确定日期之前，我们需要……
- `From a business perspective, ...` — 从业务角度看……
- `Is this timeline realistic?` — 这个时间安排现实吗？
- `Let us agree on the decision point.` — 让我们确定决策时间点。
- `We will confirm the schedule after ...` — 我们会在……之后确认时间安排。

## 3. Abbreviations in Context

| Abbreviation | Full form | 中文含义 | Usage note |
|---|---|---|---|
| TBD | To be determined | 待决定 | 计划中尚未作出决定时使用，常见于文档和状态表。 |
| TBC | To be confirmed | 待确认 | 已有初步信息但仍需确认时使用，注意不要与TBD混淆。 |

## 4. Replace and Practice

- `a small API release` → `a database change` / `a website update`
- `one more performance test` → `one more security review` / `one approval`
- `on Thursday morning` → `on Friday afternoon` / `next Monday`
- `move the release to next week` → `review the plan again` / `reduce the scope`

## 5. Questions

1. Why is the release date not final?
2. What does the speaker recommend from a business perspective?
3. What happens if the test fails?
4. What is the difference between TBD and TBC?

## 6. Retelling Challenge

不看原文，用一分钟讨论一个虚构发布计划，说明测试、决策点、TBD和TBC。
